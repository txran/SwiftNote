# M0 技术预研原型

配套文档：`docs/M0-技术预研任务书.md`（实测清单 A-1~A-7 / B-1~B-6）

本机无完整 Xcode，原型内置全部测量仪表（计时打点 / 帧间隔检测 / 内存读取），
**无需 Instruments / Memory Gauge 即可完成 M0 全部实测项**。每项测 3 次取中位数，回填任务书第五节记录表。

## 运行

```bash
# 在工程根目录（仓库根）执行
swift run --package-path prototypes/m0 --disable-sandbox PrototypeA   # 原型 A
swift run --package-path prototypes/m0 --disable-sandbox PrototypeB   # 原型 B
```

- 首次运行需编译约 30s，后续秒级；窗口弹出即用。
- `--disable-sandbox` 是 SwiftPM 沙箱开关（本机环境嵌套沙箱冲突，与本应用无关）。
- 测试数据自动从 `tools/testdata/` 定位（big_50mb.json / huge_200mb.log / small_1mb.json）。

## 原型 A — TextKit II 大文件（验证 RK-01，对照任务书 3.2）

| 实测项 | 操作 | 读数位置 |
|--------|------|----------|
| A-1 打开 52MB | 点「A-1/A-5: 打开 52MB JSON」 | 日志区：读盘/解码/装载/首屏布局分段耗时 + 总耗时（阈值 ≤2000ms） |

## 原型 B — 多行标签自绘（验证 RK-02，对照任务书 4.2）

启动即 30 个假标签（a.json ~ ad.json，B-1 场景）。v2 已借鉴 SwiftDown 项目的 TabFlowLayout / TabItemView 做法：**变量宽度标签（min 160 / max 240，按文件名实测宽度自适应）+ flow 分行算法 + easeOut 隐式动画 + hover 高亮**；FR-02 的「第 3 行横向滚动 + 溢出计数 + 跨行拖拽精确插入」为 SwiftDown 未实现的差异点，仍由本原型验证。

底部状态栏实时显示「标签 N 个 · R 行 · 首行 X 个」——B-1 不再需要数格子，直接读这里。

| 实测项 | 操作 |
|--------|------|
| B-1 换行布局 | 直接观察 30 标签的 3 行布局；读状态栏「首行 X 个」（短文件名下 1200px ≈ 7 个/行）；点「长文件名×3」观察标签自适应变宽、换行随之重排 |
| B-2 跨行拖拽 | 按住标签从第 1 行拖到第 3 行中部松手，重复 10 次（观察：排序生效、无跳位、无幽灵标签；插入位按目标标签中线判定） |
| B-3 增删切换 | 点「+1 标签」/ 标签 ✕ 关闭按钮交替 30 次 + 快速点选切换 |
| B-4 行高动画 | 跨 1→2→3 行边界增删标签（先「重置 30」到 3 行，关到 2 行、7 个以内到 1 行，再加回来） |
| B-5 极端数量 | 点「+90 标签」到 120 个（3 行上限 + 第 3 行滚动 + 溢出计数应生效） |
| B-6 窗口缩放 | 拖窗口宽度 600~1600px 连续变化（换行实时重排、无闪烁） |

**第 3 行滚动怎么操作**：鼠标停在第 3 行标签上，用触控板左右滑动或鼠标滚轮 → 第 3 行内容横向滚动，右上角 `+N` 徽标随之更新（自绘裁剪容器，不使用系统 NSScrollView，因此滚动条不会占用行高）。

### v3 可调项：行数上限（设置项，默认 5）+ 拥挤时等比压缩（2026-11-17）

回答「只能三行吗 / 一行太多能不能等比缩小」，两项都做成运行时开关（底部第二排控件）：

- **行数上限（`maxTabRows`，设置项）**：默认 **5**，范围 1~6。原型用独立 `UserDefaults` 域 `cn.swiftnote.prototype` 模拟正式版偏好设置——**改完即存、重启保持**（对应设计说明书 4.4）；已验证：写入 2 → 重启后按 2 行重排。
- **拥挤时等比压缩**：勾选后，若标签超出上限行数，则二分搜索最大缩放系数 k，所有标签宽度乘同一 k，并卡在最小宽度 112pt；缩到下限仍放不下才折叠到末行横向滚动 + 溢出计数。
  优先级顺序 = 换行 → 压缩（下限决定可读性）→ 滚动 + 计数。

启动参数便于批量对比截图：`PrototypeB --rows 1|3|5|6 --shrink 0|1 --tabs N`（`--rows` 只覆盖本次运行，不写偏好）。

30 个短名标签在 1200pt 窗口下的实测：

| 策略 | 行数 | 单标签宽 | 名字可读性 | 标签区高度 | 隐藏标签 |
|------|------|----------|-----------|-----------|---------|
| 1 行 + 压缩 | 1 | 112（下限） | 差（`c.pr...rties`） | 40pt（7%） | +19 仍需滚动 |
| 2 行 + 压缩（`maxTabRows=2`） | 2 | 112（下限） | 差 | 72pt（12%） | +9 仍需滚动 |
| 3 行 + 压缩 | 3 | 115 | 差（`c.pr...rties`） | 104pt（17%） | 0 |
| 3 行不压缩（原 FR-02 基线） | 3 | 160 | 好 | 104pt（17%） | +8（末行滚动） |
| **5 行（新默认，不压缩）** | 5 | 160 | 好 | 168pt（28%） | 0 |
| 6 行上限（30 标签自然 5 行） | 5 | 160 | 好 | 168pt（28%） | 0 |

结论：**压缩能省行数，但省不出「大量标签」**——1200pt 下单行最多 10 个标签（112pt 下限时）；压缩的有效区间是「刚好差一两个」的场景（21 个标签 → 压到 3 行），不是「30+ 标签硬塞」。默认 5 行的代价是标签区占窗口 28%，适合「管几十个小配置文件」的主场景。

### v2.1 布局修复记录（2026-11-17）

首版实测发现「三行错位、第三行被压成一条缝」，两个根因：

1. **第三行用 `NSScrollView` + 传统滚动条**：横向滚动条固定占用约 15pt，28pt 的行只剩 13pt；改成浮层滚动条后滚动条又直接绘制在标签上。
   → 改为 **自绘裁剪容器 `ClipRow`**（`masksToBounds` + 自行处理 `scrollWheel`），滚动不占任何行高。
2. **行 y 由 `frame.height` 反推**：容器高度要等父视图回调后才更新，行先按旧高度算好，整组行随窗口偏移。
   → 改为 **`isFlipped` 自上而下坐标系**，行 y 只由行号决定（`padTop + r × (tabH + gap)`），与容器当前高度解耦。

同时修掉三处小问题：溢出徽标压住标签主体（改悬浮胶囊）、脏标记用 `frame.width` 算 x（改 `bounds.width`）、首次布局宽度为 0 时把每个标签拆成一行（加宽度守卫）。

## 已知实现口径（原型级简化，不影响验证结论）

- 原型 A：只支持 UTF-8（编码不在原型范围）；帧检测的卡顿窗口为 100~500ms 连续绘制间隔（>500ms 视为用户停顿）；
- 原型 B：标签宽度变量自适应（min 160 / max 240，按文件名文本实测），短文件名即 160 下界；拖拽排序不持久化（正式版写入会话快照）。
