## P0-1 对比窗口加「上一处 / 下一处差异」导航

**现状**：工具栏只有 ⇄ 交换、同步滚动、重新对比（`CompareWindowController.swift` L77~L104）。两处以上差异时只能肉眼扫——kdiff3 / Beyond Compare / Xcode 都有 prev/next 导航，这是对比工具的标配。

**改法**：
- 工具栏状态标签旁加两个图标按钮（`chevron.up` / `chevron.down`，SF Symbols），显示「第 n / N 处」
- `DiffEngine` 输出的差异块有序，直接按块中心行跳转：联动两侧 pane 滚动（复用同步滚动的行映射逻辑）
- 快捷键：`⌘↓` / `⌘↑`（注册进 `ShortcutAction` + `MainMenuBuilder`，复用 D-31 的快捷键体系）
- 无差异时两个按钮置灰

**验证**：`SWIFTNOTE_COMPARE="/tmp/cmp_a.json|/tmp/cmp_b.json"`（两文件有 2 处差异），截图核对按钮状态与跳转后行号。注意 `ComparePaneView` 禁止碰 `textView.layoutManager`（会降级 TextKit 1，行号栏静默空白）。

## P1-2 快速打开面板高度随结果数收缩

**现状**：面板固定 580×404（日志 `frame=(448, 294, 580, 404)`）。命中 1 条时中间一大片空白（见 `sn_ui_quickopen.png`），观感「功能正常但比例失衡」。

**改法**：高度 = 表头搜索框 + `min(结果数, 8)` 行 + 底部提示栏，窗口用 `setFrame(_:animate:)` 动画收缩；高度下限保住 1 行 + footer。宽度维持 580 不动。

**验证**：`SWIFTNOTE_QUICK_OPEN=gateway`（1 条）与不设过滤词（22 条）各截一张，前者应明显变矮。

## P1-3 「已打开」徽标对比度

**现状**：选中行是纯色系统蓝，徽标白字直接压在上面，无背景区分，扫视时读不出来（见 `sn_ui_quickopen.png` 选中行右侧）。

**改法**：徽标改成「半透明白底胶囊」（`white 15%` 圆角背景 + 白字），或选中行高亮时徽标反色为蓝字白底。前者改动最小。

## P1-4 图标语言统一走 SF Symbols

**现状**（三处混用）：
- 搜索面板：SF Symbols ✅（`chevron.up` / `chevron.down` / `xmark`，`SearchPanelView.swift` L100~105）
- 对比窗口：**文本字符**「⇄」按钮（`CompareWindowController.swift` L77）
- 标签：**emoji**「🔒」（`TabItemView` L546）和**文本字符**「⚠」（L552）

**改法**（统一 `NSImage(systemSymbolName:accessibilityDescription:)`，tint 用语义色）：
| 现状 | 替换为 | tint |
|---|---|---|
| `swapButton.title = "⇄"` | `arrow.left.arrow.right` | `secondaryLabelColor` |
| `lock`（🔒 emoji，9pt） | `lock.fill` | `secondaryLabelColor` |
| `warn`（⚠ 字符） | `exclamationmark.triangle.fill` | `systemOrange` |

**注意**：`TabItemView.draw` 是自绘路径，emoji/⚠ 走 `NSAttributedString.draw`；换成 SF Symbol 后要改 `NSImage.draw(in:)` + `contentTintColor`（或在当前 appearance 下 `withSymbolConfiguration(.preferringMulticolor())`）。标签里图标 12×12 即可，纵向居中与脏点对齐。
**验证**：`SWIFTNOTE_TAB_MENU` / `SWIFTNOTE_COMPARE` 截图核对。

## P2-5 非活跃标签对比度

**现状**：`TabItemView.draw`（`TabBarView.swift` L534）非活跃态 `NSColor.windowBackgroundColor.withAlphaComponent(0.35)` 叠在 `controlBackgroundColor` 上，两者色相接近，17 个标签时糊成一片（见 `sn_ui_light.png` 上两行）。

**改法**：透明度提到 **0.5~0.65**（深浅外观都要走查），并加 0.5pt `quaternaryLabelColor` 描边兜底；hover 态保持现状（已可辨识）。

## P2-6 活跃标签下划线对齐

**现状**：`TabItemView.draw` L529——填充描边是 `bounds.insetBy(dx: 0.5, dy: 0.5)` 的圆角矩形，但 2px 蓝色下划线画在 `NSRect(x: 6, y: 0, w-12, 2)`，**顶满底边**，与内缩的圆角描边不对齐，视觉上「悬空/溢出」（截图可辨）。

**改法**：下划线改为 `y: 0.5, height: 2`，且左右不越过圆角起点（`x: 6` 已 OK）；或整体上移 1px 与描边底边内侧重合。若想更贴 macOS 原生 tab 语义，也可把指示条移到标签**顶部**（Xcode 风格）——二选一，但别贴边。

## P2-7 Properties 值色降饱和

**现状**：`SyntaxTheme.swift` L40 `propValue = stringValue`（浅色 `#A32117` 红砖色）。JSON 里字符串是少数派没问题，但 .properties 的值占正文 70%+，整屏发红（见 `sn_ui_light.png`）。

**改法**：`propValue` 单独给色，浅色 `#8A5A44`（低饱和褐）、深色 `#C9A28F`；`section` 保持紫、`propKey` 保持蓝不变。注意 `color(for:)` 的 `.propValue` case 已走独立分支，改一处即可。
**验证**：`SWIFTNOTE_APPEARANCE=light|dark` 各截一张 `parser.properties`。

## P3-8 换行标签两端对齐（可选）

**现状**：flow 布局左对齐装箱，右侧参差（`sn_ui_light.png` 前两行 7+7、末行 2）。Xcode 换行标签也是这个形态，**可接受**。

**改法**（若要做）：每行非末标签宽度拉伸 `minTabWidth → 行宽/标签数`（上限仍 `maxTabWidth`），让每行首尾对齐窗口。注意末行是 `ClipRowView` 裁剪滚动，**不参与**拉伸。
