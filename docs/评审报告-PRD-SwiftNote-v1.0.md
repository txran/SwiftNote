## 三、角色冲突裁决记录

| 冲突项 | 测试视角 | 研发视角 | 裁决 | 理由 |
|--------|----------|----------|------|------|
| GBK 纠错能力（RV-03） | MVP 必须支持编码切换，否则 FR-10 验收不闭环 | 反对扩范围：完整编码切换 UI 成本高 | 部分采纳：仅加「以指定编码重新打开」下拉入口（UTF-8/GBK 起步） | 裁决序可测性优先，但最小入口即可闭环验收；实现成本让步换取可测性，范围不扩大 |

## 六、补记（2026-11-17 16:19，用户变更请求）

1. **编码切换提前至 MVP**：用户明确要求支持编码切换，覆盖本报告 RV-03 中「完整切换工作流留 v1.1」的部分采纳裁决；影响 FR-10 / 4.1 范围。
2. **格式化场景文件规模口径**：用户确认需要格式化的 JSON/XML 文件不超过 1MB；FR-05 性能验收以此为基准（1MB 格式化 ≤0.5s 估算），大文件保护（FR-12）继续面向日志/数据文件查看场景。
3. **变更评估**：影响范围 FR-05 / FR-10 / 术语表 / 4.1 / 性能指标；工期影响小（编码重解码 + 状态栏切换 UI 成本可控）；风险变化无（编码切换逻辑简单）；干系人一致（用户本人提出）。
4. **处理**：全部采纳，PRD 修订至 v1.2（变更记录见 PRD 第一节）。
