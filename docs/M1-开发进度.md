## 一、工程形态

| 项 | 内容 |
|----|------|
| 构建系统 | SwiftPM（`swift-tools-version:5.9`，Swift 5 语言模式），平台 macOS 14+ |
| Target | `SwiftNoteKit`（Core + Infrastructure，零 UI 依赖）/ `SwiftNote`（App + Features，纯 AppKit）/ `CoreTests`（自带断言 runner） |
| 运行 | `swift run --disable-sandbox SwiftNote [文件…]` |
| 打包 | `./tools/build-app.sh release` → `dist/SwiftNote.app` + `dist/SwiftNote-<ver>-<arch>.zip`（`ditto` 打真实路径并解包验证可执行位） |
| 日常调试包 | `./tools/build-app.sh dev` → `~/Library/Caches/SwiftNote-dev/SwiftNote Dev.app`（bundle id `cn.swiftnote.app.dev`） |
| 清场 | `./tools/build-app.sh clean`：注销 LaunchServices 注册并删掉 dev/release 两份产物 |
| 图标 | `swift tools/make-icon.swift` → `Resources/AppIcon.icns`（10 档 iconset；`CFBundleIconFile=AppIcon`） |
| 测试 | `swift run --disable-sandbox CoreTests`（244 项全绿） |

为什么要拆 `SwiftNoteKit`：Core 层零 UI 依赖，才能在无 XCTest 的 CLT 环境里被独立测试；后续换回 SwiftUI 外壳时 Core 不受影响。

全部 12 个 FR 的 MVP 范围均已落地。

## 三、验证记录（实测）

| 场景 | 方法 | 结果 |
|------|------|------|
| 撤销分组 | `SWIFTNOTE_UNDO_TYPE=hello`（0.3s/字，同段）| 一次 ⌘Z 长度 372→367，5 字整段回退、栈空 |
| 撤销分级 | `SWIFTNOTE_UNDO_TYPE=abc SWIFTNOTE_UNDO_GAP=0.8`（跨 0.4s 空闲）| 一次 ⌘Z 只退 1 字（370→369），仍可撤销 |
| 撤销 × 保存 | `SWIFTNOTE_UNDO_SAVE=1`（插入 XYZ → 保存 → 插入 QQ → ⌘Z×2）| ②保存后 dirty=false 且 `可撤销=true`；④⌘Z 只退 QQ（372→370）且 **dirty=false**（回到磁盘内容，指纹判定生效）；⑤再 ⌘Z 退 XYZ（367）dirty=true |

## 四、M1 期间踩到并已固化的坑

1. **SwiftUI 不可用（工具链级）**：CLT 环境缺 `SwiftUIMacros` 插件，`@State` 直接编译失败 → UI 层全 AppKit（D-10）。
2. **手拼 TextKit II 栈会得到空视图**：手工组装 `NSTextContentStorage + NSTextLayoutManager + NSTextContainer` 后交给 `NSTextView(frame:textContainer:)`，布局片段存在、storage 有内容，但整窗不渲染任何文字；必须用 `NSTextView(usingTextLayoutManager: true)`（D-12）。该初始化器是便捷初始化器 → 不做子类化，改工厂 + delegate。
3. **`NSRulerView` 会冲掉整窗内容**：行号尺一旦在 `drawHashMarksAndLabels` 里真正绘制（哪怕只填充背景），标签栏与正文同时变白；改为自绘 `LineNumberGutterView` 跟随滚动重绘（D-11）。

4. **行号栏枚举片段必须 `.ensuresLayout`**：`enumerateTextLayoutFragments(from:options:)` 不带该选项时只返回未排版片段，`layoutFragmentFrame` 全为 0，4 万行文档把上百个行号叠画在同一个 y 上（行号区一团黑块），还白烧排版时间；改成 `options: [.ensuresLayout]`、越过视口底部即停（D-15）。
5. **大文档首次排版会把 viewport 锚到文末**：打开 900KB/4 万行文件直接跳到最后一屏，行号栏随之与正文错位；在首帧布局后与 `async` 各做一次「视口定桩」（按 `document.scrollPosition` 滚动 + `layoutViewport()`）后稳定（D-16）。
6. **切换标签不能清空搜索词**：早期在「激活文档变更」时调用面板 `deactivate()`，会把结果清空但保留关键词，表现为切回来就显示「无结果」；改为在面板的 `editor` 切换时清旧编辑区的高亮与刻度、并对新编辑区重跑查询。

7. **vnode 监视会被原子写「悄悄弄死」**：`replaceItemAt` 是 rename 语义，被监视的 inode 随之消失，`DispatchSource` 收到 `.delete` 后即失效。若把 `.delete` 直接当删除处理，表现是「保存一次之后，外部修改再也发现不了」，且界面毫无异常。修法：delete/rename 先判路径是否还在 → 在则视为内容变更并重挂监视（D-17），并在 `save` 成功后主动重挂一次。回归测试「换 inode 后仍能收到下一次修改」专门盯这条。
8. **`NSTextView.string = …` 也会发 `textDidChange`**：外部重载 / 编码切换若不做抑制，刚恢复的 Clean 文档会被立刻标脏（此前靠调用方补 `markSaved()` 打补丁，新增调用点必漏）。改为 `suppressTextDidChange` 标志包住赋值语句（D-18）。

9. **一读 `textView.layoutManager` 就把 TextKit II 打回 TextKit 1**：对比栏行高最初用 `textView.layoutManager?.defaultLineHeight(for:)`，访问瞬间 AppKit 降级到兼容模式，`textLayoutManager` 变 nil，行号栏静默空白（不报错、不崩溃）。改为 `textLayoutFragment` 度量 + 独立 `NSLayoutManager` 兜底（D-19）。
10. **左右行 ID 表不能各建一份**：diff 引擎最初左右各自「内容 → 整数 ID」，两边的 `2` 可能对应不同行，导致 `b`/`c` 被判为相同、整篇误判为一致。改为左右共用一张表（D-19 之外的单测覆盖）。另一处：纯 LCS 会把 `3000→5000` 只标出首字符，需按词边界扩张片段，否则差异提示等于没有。
11. **对比栏不折行、不插占位行**：折行会让「行号 ↔ 像素」失去线性关系，同步滚动必然错位；插占位行则必须改写文本、毁掉可编辑性。最终采用「原文各自标注 + 行号映射联动」（D-20 / D-21）。

12. **千万 pt 高的 view 画不出来**：纯文本面板最初让画布自己撑成 700 万 pt 高，`draw` 被正常调用、日志一切正常，但屏幕上整栏空白——layer-backed 的 view 分不到这么大的 backing store，绘制结果被静默丢弃。改成 `spacer`（只有尺寸）+ 一屏大小的 `canvas`（D-24）。
13. **dynamic `NSColor` 在自绘上下文里解析失败**：差异底色代码执行了、像素没变。用硬编码 `NSColor.red` 做探针才把「颜色解析」和「填充顺序」区分开；修复是整段绘制包进 `window.effectiveAppearance.performAsCurrentDrawingAppearance {}`（D-25）。
14. **独立行号栏 draw 上不了屏（归因已修正）**：小 view、frame 正常、`draw` 被调用，画面仍全白。当时记为「同层合成问题」并改为画进同一 canvas（D-26）。后续定位到真因见第 17 条——**分界线不在「哪个视图」，而在「绘制发生在枚举闭包里还是外」**。
15. **`draw(in:)` + 右对齐段落样式会把文字裁没**：行号栏整片空白无报错，改回 `draw(at:)` + 手动算右对齐位置。
16. **光标移动一次 = 全文扫一遍换行**：光标回调最初用 `while … text.range(of: "\n")` 从头数到光标位置，200MB 文档里每按一次方向键就扫一遍全文。`sample` 抓到 718 帧中 138 帧落在 `rangeOfString`（≈1.4s）。改为「行起点表 + 二分查找」，并给超过高亮上限（=无行号栏、只读）的文档直接短路。修复后 904 帧全在 `mach_msg2_trap`（空闲），`rangeOfString` 命中 0 次。
17. **在 `enumerateTextLayoutFragments` 闭包里画的东西上不了屏**：行号栏日志显示「viewport 正常、枚举 19 次、draw 调用 19 次」，屏幕却整片空白。逐一排除 appearance、dynamic 色、`wantsLayer`、`layerContentsRedrawPolicy`、坐标换算后，用探针确认：**外层 `bounds.fill()` 能上屏、闭包前后的实色块也能上屏，唯独闭包里的文字永远不出现**。改成「先收集 `[(text, y)]`、闭包结束后统一 `draw(at:)`」即刻恢复（D-27）。教训来自 R-35/P-40：这条路径一直没有像素级断言，测试全绿、行号栏其实从没显示过。
18. **`viewportRange` 在 `pinViewport()` 里读到 {0,0}**：定桩前没先跑布局，`viewportRange` 还是初始值，行号栏按「文档起点」枚举又量不到 frame。修法是滚动前先 `layoutSubtreeIfNeeded()`（scrollView 同样来一次）。
19. **菜单快捷键取「未按 shift 的字符」**：给 ⇧⌘] 设 keyEquivalent 时若用 `event.charactersIgnoringModifiers` 会拿到 `}`（该属性只忽略 shift 以外的修饰键），菜单就永远匹配不上。正确做法是 `characters(byApplyingModifiers: [])` 拿未加 shift 的 `]`，再单独给 `.shift` 掩码。录制控件里必须先走 `keyCode` 表把回车/方向/F 键映射成具名键，剩下的才按字符处理。
20. **录制快捷键必须用本地事件监听**：`NSMenuItem` 的 key equivalent 在事件派发早期就被菜单栏消费，控件里重写 `keyDown` 收不到 ⌘S 这类组合（按下去直接触发保存）。录制期间用 `NSEvent.addLocalMonitorForEvents` 整层吞掉，并在切页签/关窗口时移除，否则监听器会一直吃着按键。
21. **多个标签共用一条撤销栈**：`NSTextView.undoManager` 顺着响应链拿到的是**窗口**的栈，而本应用是一个窗口挂 N 个常驻标签。实测在「未命名」标签按 ⌘Z，被撤销的是后台 `cbm-types.json` 的内容（`ZZZ{` → `{`），眼前的文档毫无变化。修法：容器重写 `undoManager` 返回自己的栈（D-32）。
22. **只换 `undoManager` 还不够，`undo:` 根本没打到自定义栈上**：整条响应链里只有 `NSWindow` 实现 `undo:`，它转发的是窗口自己的 manager。诊断日志 `undo:目标=nil/NSWindow` 是关键线索——容器必须自己实现 `undo:`/`redo:` 才轮得到（D-32）。
23. **撤销/重做不触发 `textDidChange`**：最小复现里连打 3 字收到 3 次 `textDidChange`，撤销一次收到 **0 次**（`NSTextView` 的撤销直接替换 `textStorage`，绕过 `didChangeText`）。后果是撤销后高亮、行号栏、行列号、脏标记、搜索命中全是旧的。改订阅 `NSUndoManagerDidUndoChange` / `DidRedoChange`（D-33）。
24. **脱离了窗口的 `UndoManager` 永远不会自动分组**：`groupsByEvent = true` 的「每个事件一轮」是 NSApplication / NSWindow 驱动的，自定义 manager 全程 `groupingLevel = 1`，整篇编辑被并成一个 undo 组（「无限撤销」实际是「一步到底」）。自己调 `endUndoGrouping` 补收口会崩在 `-[NSUndoManager _prepareEventGrouping]`；最终方案是 `groupsByEvent = false` + 编辑前开组、0.4s 空闲/保存/切标签收口（D-34）。
25. **当前行高亮垫在文本视图下面会被整块盖住**：TextKit II 的 `NSTextView` 始终画自己的背景（`drawsBackground = false` 实测无效），色带垫在下层时截图像素仍是纯白。改成压在文本上层（6% 灰 + `hitTest` 返回 nil），像素采样为 `(240,240,240)` 才确认生效（D-35）。
26. **`"\r\n"` 在 Swift 里是单个 Character**：`text.contains("\r")` 对纯 CRLF 文本返回 `false`，用它做归一化的短路条件，归一被静默跳过 → 写盘时 `\n` 又被换成 `\r\n`，磁盘上就出现 `\r\r\n`（Windows 侧读成多一个空行）。判 CR 一律走 `unicodeScalars.contains("\r")`，且 `applied(to:)` 内部自己先归一一次（D-38）。
27. **纯文本文件的行号栏整栏显示 1**：`engine.setText` / `applyChange` 原来包在 `if shouldHighlight` 里，而 `.plain` 没有 lexer → 引擎从不接收文本 → `lineIndex(atOffset:)` 恒返回 0。以前 `.txt` 会被内容嗅探成 JSON/Properties 恰好掩盖了它，把 `.txt`/`.log` 定为纯文本后立刻现形。改法是把「维护行索引」与「开高亮」拆成两个条件（D-39）。
28. **「切换编码」只有一个实现必然错一半**：老逻辑是「重新读盘 → 按新编码解码」，但用户点编码名的诉求有两种——`文件其实是 GBK、现在显示乱码`（要重解码）和 `文件是 UTF-8、想改成 GBK 交付`（要改将来写盘的编码）。后者走解码路径拿到乱码，旧代码还在成功分支 `markSaved`，文档变 Clean，用户以为改好了、存下去就是乱码。改成两个菜单动作（D-40）。
29. **BOM 不记标记就会被静默抹掉**：`detectAndDecode` 原本剥掉 BOM 就完事，保存走 `encode` 自然不带 BOM。「打开带 BOM 的文件 → 原样保存」一轮，`file` 从 `UTF-8 (with BOM)` 变成 `JSON data`，只认 BOM 的 Windows 工具会改判成 GBK。现在 `hasBOM` 一路带到 `AtomicSaver`。
30. **「切换标签后当前行高亮不跟随」的根因不在高亮**：`restoreViewport()` 写的是 `if document.cursorOffset > 0`，把 0 当成了「没存过光标」的哨兵。而 `textView.string = ...` 之后 AppKit 把插入点留在**文末**，于是光标本在文首的文件（新建文档、会话恢复里所有非活跃标签默认都是 0）切过去时插入点跑到末尾，色带跟着画到文末（视口外）——用户看到的却是「高亮还停在老地方」。0 是合法光标位置，不能用 `> 0` 判断（D-41）。
31. **切标签的选中态只有鼠标点击时才更新**：`TabBarView` 在点击里自己更新选中态，而菜单「下一个标签」/⌘⇧[ ⌘⇧] / 快速打开走的是 `store.activate` → 只发 `swiftNoteActiveDocumentChanged`，没触发 `refreshTabs()`，于是内容换了、标签栏还停在旧标签。改由 `onActiveDocumentChanged` 统一刷一次。
32. **GB18030 不是 GBK，它编得下所有 Unicode**：所以「GBK 编不了这个字符」这条分支基本是死代码（实测 emoji 也能编）。真正的坑在另一端：BMP 以外字符被写成 4 字节，只认 GBK 双字节区的 Java/MFC 报文工具会读错，因此转 GBK 前用 `hasSupplementaryPlaneCharacters` 给警告。
33. **打开一个已经开着的文件会跳到最后一个标签**：`open()` 里对已存在的文档走 `activate(index:)`，但循环结束后又无条件 `activeIndex = documents.count - 1`，把刚切过去的位置覆盖掉了。改成记录「本次最后一个目标下标」——新追加的取末尾、已存在的取它自己。
34. **切标签后状态栏行列号是上一个文档的**：行列号只由 `textViewDidChangeSelection` 驱动，光标位置恰好没变时不发通知。`EditorContainerView` 新增 `reportCursorPosition()`，`mountActiveEditor` 挂载后主动播报一次。
35. **纯插入块的导航位置要 +1**：`rightToLeftLine` 给插入行映射的是它**前面**那一行（左侧没有对应行），直接拿来做跳转目标会落在插入点之前的相同行上，用户按「下一处差异」看不到任何变化。跳转目标要取 `mapping + 1`（插入点之后的首行）。
36. **⌘↓/⌘↑ 不能拿来做应用级快捷键**：`NSMenuItem` 的 key equivalent 在键盘事件进入响应链之前就被菜单消费，注册成 ⌘↓ 会让整个编辑区的「到文末」失效。差异导航改用 ⌥⌘↑/⌥⌘↓。
37. **自绘 SF Symbol 要自己上色**：`NSImage.draw(in:)` 不理会 `contentTintColor`（那是 NSButton/NSImageView 的事），模板图会画成黑色。得用 drawingHandler 画完再 `rect.fill(using: .sourceAtop)` 染一遍。

附带修的算法 bug：全量重词法时按「上下文与旧缓存一致」提前收敛，导致 XML 多行注释后整段不再着色——已加 `forceFull` 强制全扫。

## 六、已知限制

- 打包的 `.app` 首次访问 `~/Documents` 会触发系统授权弹窗（未签名应用的正常行为），允许一次即可；
- App 图标已接入（`AppIcon.icns`，Dock/Finder/切换器均生效）；仍为 ad-hoc 签名，对外分发需 Developer ID + 公证，否则对方要右键「打开」或 `xattr -d com.apple.quarantine`；
- `dist/` 不要放在被 Spotlight 索引的位置，否则同一份应用会被 LaunchServices 认成两个身份（已在 `build-app.sh` 的 `clean` 里做注销，见 P-30~P-34）；
- 设置项已有 UI 入口（⌘,），也可继续用 `defaults write cn.swiftnote.app maxTabRows -int 3` 验证；
- 深色主题：快速打开面板、状态栏、纯文本行号栏、XML 层级化文本、编辑区当前行色带（亮度 43:30）、标签栏（未选中文字对比度 6.15:1 / 选中 12.27:1）均已走查（`SWIFTNOTE_APPEARANCE=dark` + 像素采样）；
- 搜索暂不支持「跨标签全局搜索」，只作用于当前编辑区；\n- 外部修改提示使用模态 `NSAlert`（非 sheet），批量冲突时逐条弹出；\n- 文件被删除后若在原路径重建同名文件，需等窗口重新激活（或手动 Cmd+R）才恢复监视；
- 大文件只读判定目前**只看体积**：3MB 压缩成一行的 JSON 会卡住主线程（实测 >10s），但按阈值它仍是「可编辑」。想避开只能手动把阈值调到 3MB 以下，或等后续加「超长行」判据；
- 对比栏对 12MB / 16 万行文件：diff 本身 3.6s，但首次把文本灌进 TextKit II 时另有 5~7s 首帧段落缓存刷新（AppKit 内部 `ensureLayout`），期间界面无响应；配置类文件（< 1MB）无此问题，后续可用「超阈值只读预览」规避；
- 对比栏从「已打开的文档」取内容时是内存副本，该栏固定只读（避免两个编辑区争同一份文本），要编辑请从磁盘打开；
- 对比不插占位行，插入/删除后两栏行号会错位，靠同步滚动与行映射补偿。
