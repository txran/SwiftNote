## 二、背景与目标

### 2.1 背景

- 团队日常工作涉及大量结构化配置文件（JSON / XML / Properties）的查看与编辑（如 CBM 消息解析配置）。
- macOS 平台缺少类似 Notepad++ 的轻量编辑器：主流选择要么过重（VS Code、Sublime Text），要么功能不匹配（TextEdit），且**均不支持多行标签页**——这是 Notepad++ 处理大量文件时的标志性效率能力。
- 现有工具在「打开大量配置文件 + 快速切换 + 语法着色」组合场景下体验割裂。

### 2.2 要解决的问题

1. 同时打开的配置文件超过一屏标签时，单行标签无法全部展示，查找文件靠记忆和滚动；
2. JSON/XML 配置错误难以快速定位；
3. 大体积日志/数据文件在通用编辑器中打开卡顿明显。

### 2.3 成功指标与口径

| 指标 | 口径定义 | 目标值（建议值，待确认） | 说明 |
|------|----------|--------------------------|------|
| 冷启动时间 | 点击图标到可输入首字符 | ≤ 1s | 估算 |
| 大文件打开时间 | 打开 50MB JSON 文件到可滚动 | ≤ 2s | 估算 |
| 编辑流畅度 | 50MB 文件内滚动、跳转不出现可感知卡顿（>100ms 单帧） | 全程流畅 | 主观验收 |
| 使用替代率 | 上线后 2 周，日常配置文件编辑任务中 SwiftNote 的使用占比（自记录） | ≥ 80% | 自用工具以实际使用为准 |

## 三、名词与术语定义

| 术语 | 定义 |
|------|------|
| 多行标签页（Multi-row tabs） | 标签数量超过窗口单行容量时，标签自动换行到后续行展示；行数上限为设置项（默认 5 行，可调 1~6），上限以内全部可见，超出部分在最后一行内横向滚动并显示溢出计数 |
| 脏标记（Dirty indicator） | 文件被修改但尚未保存时，标签页上显示的未保存状态标记（●） |
| 增量解析 | 只对发生变更的文本区域重新做语法解析，而非全文件重解析 |
| 会话恢复 | 应用退出后再次启动时，恢复上次的标签页列表与各文件未保存内容 |
| 双屏对比 | 左右分栏展示两份文件，按行对齐并标色差异（类似 Notepad++ Compare 插件） |
| 文件规模口径 | JSON/XML 格式化与编辑场景的目标文件典型 ≤ 1MB（用户确认口径，2026-11-17）；大文件性能场景（FR-12）主要指日志/数据文件查看 |

## 五、方案对比与选型说明

### 5.1 技术栈对比

| 方案 | 实现成本 | 复杂度 | 性能上限 | 风险 | 结论 |
|------|----------|--------|----------|------|------|
| A：原生 Swift + SwiftUI + TextKit II | 中 | 中 | 极佳 | 低 | ✅ 已选定 |
| B：Electron + Monaco | 低 | 低 | 中 | 中 | 不选：内存占用高，与高性能目标冲突 |
| C：Rust / Tauri 自绘 | 高 | 高 | 极佳 | 中 | 不选：编辑器内核自研成本过高 |

**选定理由**：自用工具定位下追求性能上限与体验一致性；TextKit II 对大文本有原生优化；多行标签需自绘控件（AppKit 无现成实现），原生方案控制力最强。

**演进路径**：v1.0 原生单平台 → 后续若需跨平台再评估（触发条件：出现明确的 Windows 使用诉求）。

### 5.2 语法高亮实现路线（技术约束建议，由开发最终确认）

- Properties：行级规则（key=value、# 或 ! 注释、\ 续行），轻量词法器即可；
- JSON / XML：词法器 + 行级 token 缓存 + 增量重解析（仅变更区域），避免全文件重解析；
- 校验复用系统解析器（Foundation JSONSerialization / XMLParser），不重复造轮子。

## 七、功能需求

> 状态词约定：必须（shall）/ 应该（should）/ 可以（may）/ 禁止（must not）。

### FR-01 多标签页管理（Must）

标签页支持新建、关闭、切换；Cmd+T 新建、Cmd+W 关闭当前、Cmd+Shift+[ ] 切换上一个/下一个；关闭有未保存内容的标签必须弹出确认（保存/不保存/取消）；标签必须显示文件名 + 脏标记（●）；退出应用（Cmd+Q）或关闭窗口时若存在多个未保存标签，必须合并为一次列表式确认（列出全部未保存文件，统一「全部保存 / 全部不保存 / 取消」），禁止逐个弹窗。

**验收标准（GWT）**
- Given 编辑器已打开文件 A，When 修改 A 的内容，Then A 的标签出现脏标记（●）；
- Given 文件 A 有未保存修改，When 点击标签关闭按钮，Then 弹出「保存 / 不保存 / 取消」三选确认；
- Given 打开了 3 个标签，When 按 Cmd+Shift+]，Then 切换到下一个标签；
- Given 存在 3 个带未保存修改的标签，When 按 Cmd+Q 退出，Then 仅弹出一次确认并列出 3 个文件，可统一处理。

### FR-02 多行标签显示（Must，核心差异化）

标签总宽超过单行容量时必须自动换行为多行展示；标签支持拖拽排序；标签行数上限是**用户设置项**（`maxTabRows`，默认 5 行，可调范围 1~6，存用户偏好）——上限以内全部标签始终可见，超出上限时最后一行内部横向滚动并在行尾显示溢出计数提示（如 +12），避免极端情况吃掉编辑区；每个标签必须有独立的关闭按钮；行数变化时标签区高度平滑过渡。单行容量口径：单行可容纳标签数 = 窗口宽度 ÷ 最小标签宽度（最小标签宽度按 160px 估算，含图标/文件名/脏标记/关闭按钮，M0 校准）。

**验收标准（GWT）**
- Given 窗口宽度 1200px（按口径约容纳 7 个标签），当标签总宽超过一行容量，When 再打开 1 个标签，Then 该标签出现在第二行且所有标签可见（未超行数上限时）；
- Given 标签处于第 1 行，When 将其拖拽到第 2 行某位置，Then 松手后排序生效且重启后保持；
- Given 行数上限为默认值 5 且已有 5 行标签、末行已满，When 再打开新标签，Then 末行内横向滚动并显示溢出计数，编辑区高度不再被压缩；
- Given 用户在设置中把行数上限从 5 改为 3，When 确认设置，Then 标签区立即按 3 行重排（多余标签折叠进第 3 行滚动），高度平滑过渡且设置重启后保持。

### FR-03 会话恢复（Must）

正常退出（含 Cmd+Q）后再次启动，必须恢复上次的标签页列表、各标签的滚动位置与未保存内容；恢复失败（如文件已被删除）必须静默跳过并提示。未保存内容的草稿快照机制：编辑停止 2 秒后（估算值，可配置）或切换标签时写入本地，会话恢复与崩溃恢复（第八节「可靠性」）共用同一份快照，禁止双机制并存。

**验收标准（GWT）**
- Given 标签 A 有未保存修改，When 退出应用并重新启动，Then A 自动重新打开且未保存内容完整恢复。

### FR-04 语法高亮：JSON（Must）

必须对 key（含双引号）、字符串值、数字、true/false/null、标点分色；颜色方案应该可读性优先（深浅主题各一套默认配色）；高亮应该随输入增量更新，延迟不可感知。

**验收标准（GWT）**
- Given 打开合法 JSON，When 渲染完成，Then key/字符串/数字/布尔/null 至少 4 类元素以不同颜色显示；
- Given 光标在 50MB 文件中修改 1 行，When 输入字符，Then 仅该区域重新着色，无明显卡顿。

### FR-05 JSON 格式化与校验（Must）

Cmd+Shift+F 一键格式化（2 空格缩进，缩进风格可以配置）；语法错误必须在行内标红并在状态栏显示行列号；点击错误提示必须跳转到错误行；格式化执行前必须保证可撤销（Cmd+Z 一步回退整个格式化）。性能口径：格式化与校验的目标文件规模 ≤ 1MB（用户确认口径，2026-11-17），1MB 文件格式化应该在 0.5s 内完成（估算）；超过 1MB 的文件仍可以格式化，但性能不做硬性承诺。

**验收标准（GWT）**
- Given 打开一个合法但未缩进的 JSON，When 按 Cmd+Shift+F，Then 文件被格式化为 2 空格缩进且可一次撤销；
- Given 打开缺失右括号的 JSON，When 解析完成，Then 错误行标红、状态栏提示行列号，点击后光标跳转该行；
- Given 打开 1MB 的未格式化 JSON，When 按 Cmd+Shift+F，Then 应该在 0.5s 内（估算）完成格式化；
- Given 在纯文本（.txt）或任意文件中选中一段 XML 报文，When 右键选「转换为 JSON」，Then 该段被替换为等价的 JSON 对象（保留根元素、键序、属性），且可一次撤销（v1.4 追加）。

### FR-06 语法高亮：XML（Must）

必须对标签名、属性名、属性值、注释（`<!-- -->`）、CDATA 分色；标签配对错误应该给出可定位提示（MVP 可以仅行内着色，深度校验列入 v1.1）。

**验收标准（GWT）**
- Given 打开合法 XML，When 渲染完成，Then 标签名/属性名/属性值/注释至少 4 类元素分色显示。

### FR-07 语法高亮：Properties（Must）

必须对 key、value、注释行（# 或 ! 开头）分色；必须识别 `\` 续行并保持同一逻辑块的着色连续。

**验收标准（GWT）**
- Given 打开含 `# 注释`、`key=value`、`\` 续行的 properties 文件，When 渲染完成，Then 注释/key/value 分色，续行块着色连续不错乱。

### FR-08 搜索替换（含正则）（Must）

Cmd+F 文件内搜索、Cmd+Option+F 替换；必须支持正则模式（可开关）、大小写敏感开关、整词开关；当前视口内命中必须全部高亮，视口外命中以滚动条位置标记指示（不强求一次性渲染全文件命中），命中计数必须为全量计数；Enter/Shift+Enter 上一个/下一个；替换支持「替换当前 / 全部替换」，全部替换必须可一次撤销。

**验收标准（GWT）**
- Given 打开 50MB 文件，When 搜索字符串 `"timeout"`，Then 视口内命中全部高亮、滚动条显示全量命中标记、计数准确，跳转间隔 ≤ 100ms（估算）；
- Given 开启正则模式，When 搜索 `"host\d+"` 并选择全部替换为 `"host1"`，Then 所有模式命中被替换且可一次撤销。

### FR-09 双屏文件对比（Must）

必须支持左右分栏对比任意两份文件；差异行必须标色（新增/删除/修改用不同底色，遵循浅色主题可读配色）；可以同步滚动两栏；从对比视图应该可直接编辑并实时刷新差异。

**验收标准（GWT）**
- Given 对比文件 A 与 B，When 差异计算完成，Then A 独有、B 独有、双方不同的行分别以不同底色标出；
- Given 对比超过 10MB 的两份文件（阈值标注估算），When 差异计算超过 3s，Then 必须自动降级为行级 diff 并明确提示，禁止无限等待或界面冻结。

### FR-10 编辑核心（Must）

必须支持无限撤销/重做（Cmd+Z / Cmd+Shift+Z）；必须显示行号且当前行高亮；必须支持自动换行开关；必须自动识别文件编码（UTF-8 / GBK 优先，识别失败时按 UTF-8 打开并在状态栏标注编码名）；必须支持编码切换：状态栏编码名可点击，选择新编码后按新编码重新解码显示，编码列表 UTF-8 / GBK（GB18030 兼容）起步且应该可扩展；存在未保存修改时切换编码必须弹出确认（保存后切换 / 放弃修改并切换 / 取消），禁止静默丢失修改；Tab 键输入必须可配置（Tab 字符 / 空格）。

**验收标准（GWT）**
- Given 打开 GBK 编码的中文配置文件，When 加载完成，Then 中文正常显示且状态栏标注「GBK」；
- Given 按 UTF-8 打开后出现乱码，When 点击状态栏编码并选择 GBK，Then 文件立即以 GBK 重新渲染且状态栏更新；
- Given 文件有未保存修改，When 切换编码，Then 弹出「保存后切换 / 放弃修改并切换 / 取消」确认，禁止静默丢失修改；
- Given 修改并保存，When 按 Cmd+Z，Then 逐步撤销修改，保存动作不消耗撤销步骤。

### FR-11 文件管理（Must）

必须支持：打开/保存/另存为（Cmd+O/S/Shift+S）、拖拽文件到窗口或 Dock 图标打开、最近文件列表（≥ 20 条，Cmd+Shift+O 快速打开）；文件在外部被修改时必须提示「重新加载 / 保留本地」。

**验收标准（GWT）**
- Given 文件 A 已在编辑器打开，When A 被其他程序修改保存，Then 编辑器弹窗提示重新加载或保留本地版本；
- Given 从 Finder 拖拽 3 个文件到窗口，When 松手，Then 3 个文件分别以新标签打开。

### FR-12 大文件保护（Must）

打开大文件必须不卡死：文件超过阈值（建议 20MB，可配置）时应该提示并提供「以只读模式打开」选项；只读模式下语法高亮可以降级为无着色以保证滚动流畅。只读模式功能矩阵：查看、复制、搜索（FR-08）应该可用；编辑、保存、格式化、替换必须禁用（入口置灰并提示原因）；双屏对比（FR-09）可以以只读方式参与对比。

**验收标准（GWT）**
- Given 打开 200MB 文本文件，When 选择只读模式打开，Then 应用不冻结、可滚动（着色可以降级），退出时恢复正常。

| 兼容 | 架构 | Universal Binary（Intel + Apple Silicon）should |
| 安全 | 文件权限 | 仅访问用户主动打开的文件，禁止未授权目录扫描 |
| 可访问性 | 键盘 | 核心操作全部可键盘完成（上表快捷键全集）should |
| 可靠性 | 崩溃恢复 | 未保存内容写入草稿快照（与 FR-03 会话恢复共用同一机制，触发时机见 FR-03），崩溃后启动可恢复 must |

## 九、业务流程与状态流转

### 9.1 文档状态机

| 状态 | 触发事件 | 迁移到 | 允许的操作 |
|------|----------|--------|-----------|
| 未修改（Clean） | 打开 / 保存成功 | — | 编辑、关闭、对比 |
| 已修改（Dirty） | 用户输入 | — | 保存、对比、关闭（需确认） |
| 只读（ReadOnly） | 大文件降级 / 文件权限 | — | 查看、复制、另存为 |
| 关闭（Closed） | 用户关闭标签 / 应用退出 | — | — |

约束：状态迁移单向唯一（Clean ⇄ Dirty 由保存/输入驱动），禁止出现「保存后仍显示脏标记」或「未保存却显示 Clean」的不一致。

### 9.2 核心流程

- 打开文件 → 识别扩展名/内容选择语法模式 → 加载渲染 →（大文件？→ 降级提示）→ 进入编辑。
- 外部修改监控：文件监视（_monitor 信号量方式由开发定）→ 冲突弹窗 → 用户选择「重载/保留」。
- 保存流程：Cmd+S → 写入临时文件 → 原子替换 → 状态回 Clean；写失败必须保留内容并提示，禁止静默丢失。

## 十、数据与埋点需求

自用工具，不做云端埋点。最小数据能力（本地）：

| 数据 | 用途 | 保留位置 |
|------|------|----------|
| 会话快照（标签列表、滚动位置、未保存草稿） | 会话恢复（FR-03） | 本地 Application Support |
| 最近文件列表 | FR-11 | 本地 |
| 启动耗时/大文件打开耗时日志（本地 debug 日志） | 验证第八节性能指标 | 本地，仅排障用 |

约束：所有数据仅存本机，禁止任何外发。

## 十一、权限与安全要求

- 沙盒能力最小化：不申请网络权限、不申请全盘磁盘访问；拖拽/打开对话框获取的文件权限按会话授予。
- 不解析可执行内容、不加载远程资源；XML 解析必须禁用外部实体（XXE 防护）。
- 自动恢复的未保存草稿存放于用户目录，随应用卸载可清理。

## 十二、异常处理清单

| # | 异常场景 | 处理要求 |
|---|----------|----------|
| 1 | JSON/XML 解析失败 | 行内标红 + 定位提示，禁止整文件拒绝打开 |
| 2 | 编码识别失败 | 按 UTF-8 打开 + 状态栏标注；乱码应该通过编码切换（FR-10）纠正，切换含未保存修改保护 |
| 3 | 文件被外部删除/移动 | 标签保留内容 + 提示，另存为可找回 |
| 4 | 磁盘写满/权限失败 | 保留内容 + 明确错误提示，禁止丢内容 |
| 5 | 会话恢复失败 | 跳过该标签 + 单次汇总提示，禁止启动阻断 |
| 6 | 对比的两份文件之一被修改 | 实时刷新差异或提示重新对比 |
| 7 | 大文件拖拽批量打开 | 逐个加载，禁止 ANR 式冻结；超阈值的降级提示合并为一次汇总弹窗（列明哪些文件以只读打开），禁止逐文件弹窗 |
| 8 | 标签数量极端场景（100+） | 行数上限（默认 5，设置可调 1~6）+ 末行横向滚动兜底（见 FR-02） |

## 十五、附录

### 15.1 多行标签页线框思路

```
┌────────────────────────────────────────────────┐
│ [a.json ●] [b.xml] [c.properties ●] [d.json] [+] │  ← 第 1 行（满）
│ [e.json ●] [f.xml]                             │  ← 溢出换行
├────────────────────────────────────────────────┤
│ 1  { "host": "cbm-server-01",                  │
│ 2    "port": 8443,                             │  ← 编辑区
│ 3    "timeoutMs": 30000 }                      │
├────────────────────────────────────────────────┤
│ UTF-8（点击切换）· JSON · 行 3, 列 28           │  ← 状态栏
└────────────────────────────────────────────────┘
```

- 标签：文件名 + 脏标记（●）+ 独立关闭按钮 + 图标按类型区分；
- 标签区高度随行数变化，拖拽支持跨行排序；
- 状态栏：编码（点击可切换）· 语法模式 · 光标行列 · 错误提示位。
